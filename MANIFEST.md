## 🔬 What the Experiment Does

### Three Configurations
1. **Baseline (auto)** — No KV-cache compression
2. **FP8** — FP8 quantization
3. **int8_per_token_head** — Target: per-token per-head int8 (NEW in vLLM)

### Test Set
- **30 AIME problems** (hard math reasoning)
- **70 GSM8K problems** (grade-school math, easier)
- **100 total**, fixed across all three runs

### Output
For each problem:
- Full generated text (chain-of-thought)
- Token count
- Latency (seconds)
- GPU memory used

### Scoring
Each output classified into one of six categories:

| Category | Meaning |
|----------|---------|
| **No Failure** | Correct reasoning + correct answer |
| **Shortcut Collapse** | Correct answer, reasoning skipped (⚠️ main risk) |
| **Premise Hijacking** | Wrong problem interpretation, correct logic |
| **Confidence Snowballing** | Early error propagates |
| **Overcounting** | Correct intermediate, then continues |
| **Incoherent** | Garbled/truncated output |

## 📊 Expected Results

### Overall Accuracy (No Failure %)
On Qwen2.5-7B-Instruct, expect ~65-75% baseline accuracy on mixed AIME+GSM8K.

### Key Question
**Does int8_per_token_head cause Shortcut Collapse like NF4 did?**

Possible answers:
- ✓ **No** — Accuracy/SC rate matches baseline (good!)
- ⚠️ **Yes** — Accuracy drops or SC rate elevated (concerning)
- 🚨 **Critical** — Large accuracy loss or dominant SC (red flag)

## ⚙️ Technical Details

### Model
- **Default:** Qwen/Qwen2.5-7B-Instruct (fits most GPUs)
- **Alternative:** meta-llama/Llama-3.1-8B-Instruct (larger)

### Inference Settings
- **Temperature:** 0.7 (reproducible but with variation)
- **Top-p:** 0.95
- **Max tokens:** 1024 (full reasoning chains)
- **Seed:** 42 (reproducible)
- **Attention backend:** FLASHINFER (avoids Triton bug)

### Why FLASHINFER?
Triton backend has known quantization bugs (#49716). FLASHINFER is more reliable.

## 🧪 Validation Checks

### Automated Scoring
`score_outputs.py` uses heuristics to detect:
- Shortcut Collapse: correct answer + no reasoning
- Premise Hijacking: wrong problem + consistent logic
- Confidence Snowballing: cascading errors
- Overcounting: multiple answers / unnecessary continuation
- Incoherent: garbled or truncated output

**Note:** Heuristics are imperfect → manual review is essential.

### Sanity Checks
`sanity_check.py` displays random samples (default 5 per dtype) for human verification.

**What to do:**
1. Read each sample's generated text
2. Judge: is it correct?
3. Compare with predicted category
4. Did the automation get it right?

Target: >90% accuracy on manual sample verification.
