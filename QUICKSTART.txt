================================================================================
    vLLM KV-Cache Quantization Safety Experiment - QUICK START
================================================================================

WHAT: Test if int8_per_token_head KV-cache quantization causes silent reasoning
      failures (Shortcut Collapse) like NF4 weight quantization did.

WHERE: All code is in this directory. Everything is self-contained and reproducible.

WHEN: ~3-4 hours on an A100 GPU for full 100-problem test. Minutes on CPU (very slow).

HOW:

  1. SETUP (first time only)
     $ make setup
     → Installs vLLM from source + dependencies in local venv

  2. PREPARE DATA
     $ make prepare
     → Downloads 30 AIME + 70 GSM8K problems to data/testset.jsonl

  3. RUN EXPERIMENTS
     $ make run-all
     → Runs three experiments sequentially:
       • Baseline: auto (no KV compression)
       • FP8: fp8 KV compression
       • Target: int8_per_token_head

  4. SCORE RESULTS
     $ make score
     → Classifies outputs into 6 failure modes
     → Generates comparison table (auto vs fp8 vs int8_per_token_head)

  5. MANUAL REVIEW
     $ make sanity-check
     → Shows 5 random outputs per dtype for human verification

  6. VIEW REPORT
     $ less report.md
     → Fill in your results (blanks marked with [FILL])

================================================================================
                              TESTING QUICKLY

  To verify everything works before running the full 3-4 hour experiment:

  $ make prepare
  $ make run-baseline NUM_PROBLEMS=5
  $ make run-fp8 NUM_PROBLEMS=5
  $ make run-int8 NUM_PROBLEMS=5
  $ make score

  This takes ~15-20 minutes and gives you the full pipeline with small data.

================================================================================
                        THE SIX FAILURE CATEGORIES

  1. NO_FAILURE            → Correct reasoning + answer
  2. SHORTCUT_COLLAPSE     → Correct answer, but reasoning skipped
  3. PREMISE_HIJACKING     → Wrong problem, correct logic
  4. CONFIDENCE_SNOWBALLING → Early error propagates
  5. OVERCOUNTING          → Correct intermediate, then continues wrong
  6. INCOHERENT            → Garbled/truncated output

  See SCORING_GUIDE.md for detailed examples.

================================================================================
                          TROUBLESHOOTING

  Out of Memory?
    → Edit run_experiment.py, reduce gpu_memory_utilization (0.9 → 0.7)
    → Or use smaller model (Qwen2.5-3B instead of 7B)

  vLLM won't install?
    → Check PyTorch: python -c "import torch; print(torch.cuda.is_available())"
    → Check CUDA version: nvcc --version (need 11.8+)

  Setup script hangs?
    → May be downloading large files. Give it time (10+ minutes).

  No results after run?
    → Check: wc -l results/auto/outputs.jsonl
    → Check: head results/auto/outputs.jsonl
    → If empty, check errors: python scripts/run_experiment.py --kv_cache_dtype auto
